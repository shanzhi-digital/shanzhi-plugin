# 销售数据查询

把一句话的问题变成准确的查询，拿到真实数据，用表格交付。

## 什么时候用

- 用户要的是**数据本身**：列表、数量、金额、某条记录在不在、谁负责、最近一次跟进是什么。
- 要分析结论和建议时换专门的 skill：项目盘点用 `salesforge-project-analysis`，目标完成用 `salesforge-target-tracking`，跟进计划用 `salesforge-customer-followup`，周报复盘用 `salesforge-weekly-review`。

## 开始前

- 需要已连接销售管理系统账户。不确定时先调用 `sales_config` 看连接状态。
- 任何工具返回 kind 为 `salesforge-auth-required` 时：把 message 原样转告用户，停下等用户回复「继续」，不要重试或绕过，也不要向用户要账号密码。
- 这个 skill 只管查。用户要新建、修改、删除、移交数据时，改用 salesforge-edit-data 的做法。

## 第 1 步：拆问题

把问题拆成三部分：

1. **查什么**：客户、渠道、项目、项目金额汇总、看板、日报、周报、周计划、目标。
2. **筛选条件**：哪个人、哪个客户或渠道、什么时间、什么阶段或风险、金额范围、未跟进天数。
3. **要什么结果**：明细列表、条数、金额合计、排名（前几名）。

对照 `references/question-map.md` 找到对应的工具和参数。一个问题要查几样东西时，拆成几次调用，分别交代来源。

## 第 2 步：把名字换成 ID

- **人名**（负责销售、汇报人）：直接把姓名填进 `salesName` 或 `reporterName`。工具会先确认这个人在你能查看的范围内。返回 kind 为 `salesforge-person-unresolved` 时：
  - `candidates` 有多位：列出姓名、用户名、部门 ID，请用户选是哪一位，再用 `salesId` 或 `reporterId` 重查；
  - `candidates` 为空：说明找不到或不在查看范围内，如实告诉用户，可以用 `sales_search`（`target="people"`）列出能查的人员供参考。
  - 不要自己从候选里挑一个。
- **客户或渠道名**：用 `sales_search`，`keyword` 填名称的一部分。一个结果就直接用它的 ID；多个结果列出来请用户选；没有结果就换个更短的关键词再试一次，还没有就告诉用户查不到。
- **「我」「我的」**：不用填人员参数，账户本人的数据范围由系统决定。但日报和周报不填汇报人时会返回你能看到的所有人的；要只看自己的，先用 `sales_config`（`action="profile"`）拿到自己的 `userId`，再作为 `reporterId` 传入。

## 第 3 步：调用工具，处理分页

- 列表默认每页 20 条，最大 100 条（日报和周报最大 50 条）。
- 结果里 `total` 是符合条件的总条数，`hasMore` 为 true 表示还有下一页。
  - 用户只要看看：给第一页，并说明「共 N 条，显示前 M 条」。
  - 用户要全部明细：用 `pageNum` 逐页取完。超过 300 条时先问用户是否真的需要全部，或者建议加条件。
  - 用户只要数量或金额合计：项目用 `sales_query_projects` 的 `mode="summary"`，不要翻页去加；其他对象直接用 `total`。
- 用了 `minDaysSinceFollow`、`expectedSignFrom`、`expectedSignTo`、`sortBy`（项目按金额、预计签约日期、未跟进天数排序）时，插件会翻页扫描最多 500 条后在本地筛选和排序，这时**不能传 `pageNum`**，只返回前 `pageSize` 条。结果里 `localFilter.scanTruncated` 为 true，要告诉用户「只扫描了前 500 条，结果可能不全」，并建议加条件缩小范围。
- 项目默认**不含「项目签约」「项目丢单」**。问已签约、丢单或「全部项目」时，设 `includeArchived=true`，或直接用 `projectStatus` 指定阶段。

## 第 4 步：交付结果

- 用表格给出结果。列太多时只保留和问题相关的列，ID 列保留（方便追问）。
- 表格下面写一行出处，例如：

  > 数据来源：`sales_query_projects`（`mode="list"`）；条件：负责销售=张三，阶段=商务招标，不含已签约和丢单；共 37 条，显示前 20 条。金额单位：万元。

- 金额单位是**万元**，照原样写，不要换算成元。
- 当前会话有 `query_result_chart` 工具（@local/datahub-echarts 插件提供）时，可以用它展示表格或图表，`sourceCallId` 填对应查询的调用 ID；展示成功后正文只写结论，不再重复整张表。
- 引用看板里的「本月目标」时，说明它是插件按年度目标除以 12 估算的。

## 查不到时

- `rows` 为空：直接说「没有查到符合条件的数据」，复述用了哪些条件，并给出可能的原因：
  - 项目默认不含已签约和丢单；
  - 只能看到自己和下级部门的数据；
  - 名称关键词不准，或条件太窄。
- 绝不根据常识、记忆或别的数据推测一个数出来。部分数据缺失时，标「无数据」，不要补。
- 工具报错时把报错原文转告用户。HTTP 403「没有查看权限」不是插件坏了，是账户权限不够。

## 做不到的事

- 查看范围以外的人的数据。
- 联系人的电话：`sales_get_record` 不返回电话。

按 ID 看一个客户、渠道、项目或日报的完整详情（联系人、部门、梳理记录、项目分析），用 `sales_get_record`。
