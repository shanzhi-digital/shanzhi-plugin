# 项目分析

把商机盘子摊开看：结构怎么样、哪些项目有问题、接下来该盯哪几个。

## 什么时候用

- 用户要项目盘点、商机分析、风险项目排查、签约预测。
- 只要一张项目列表、不要结论：用「查数据」skill（`salesforge-query-data`）。
- 关心目标缺口能不能补上：用「目标完成追踪」skill（`salesforge-target-tracking`），它会用到这里的部分数据。

## 开始前

- 需要已连接销售管理系统账户。任何工具返回 kind 为 `salesforge-auth-required` 时：把 message 原样转告用户，停下等用户回复「继续」，不要重试或绕过。
- 弄清今天的日期，后面「已过期」「本季度」都按它算。
- 弄清**范围**：默认是账户能看到的全部在跟项目（自己负责的，加下级部门的）。用户点名某个销售时，所有项目查询都加 `salesName`；返回 `salesforge-person-unresolved` 就请用户从候选里选，再用 `salesId`。
- 弄清**时间窗口**：默认本季度。用户说本年、本月或某个日期区间时照用户的。

## 只用这些数据

- `sales_query_projects` 的 `mode="list"` 和 `mode="summary"`；
- `sales_dashboard` 的 `view="opportunity"`、`view="market"`。

插件没有按 ID 查项目详情的工具，**不要尝试查详情**，也不要向用户要详情。列表里没有的信息（例如阶段变更历史、联系人），就说系统里看不到。

## 步骤

### 1. 盘子总量

- `sales_query_projects`：`mode="summary"`，得到在跟项目的项目数、预计总金额、必签金额、有风险金额。
- `sales_dashboard`：`view="opportunity"`，`period` 按时间窗口选。注意它**包含已签约和丢单**，和上面的汇总对不上是正常的，引用时说明口径。

### 2. 阶段结构

对 7 个在跟阶段（发现问题、技术预研、方案论证、立项审批、启动采购、制定标准、商务招标）各调用一次 `sales_query_projects`：`mode="summary"`、`projectStatus` 填该阶段。得到每个阶段的项目数和金额，算出占比。

看结构：金额是不是大量堆在前期阶段（发现问题到方案论证），后期阶段（启动采购到商务招标）是不是太薄。

### 3. 时间分布

`sales_query_projects`：`mode="list"`，`expectedSignFrom`、`expectedSignTo` 填时间窗口，`sortBy="expectedAmount"`，`pageSize=50`。用返回的 `matchedSummary`（项目数、预计总金额、按风险分的金额）说明这个窗口里预计能签多少、其中多少带风险。

### 4. 找问题项目

分别查，每类取金额最大的前 10 个：

| 问题 | 查法 |
|---|---|
| 预计签约日期已过还没签 | `mode="list"`，`expectedSignTo` 填昨天，`sortBy="expectedAmount"` |
| 很久没梳理 | `mode="list"`，`minDaysSinceFollow=30`（用户可改），按未梳理天数从多到少 |
| 带风险标记的大项目 | `mode="list"`，`projectRisk` 分别填「时间风险」「赢单风险」，`sortBy="expectedAmount"` |
| 阶段偏早却快到签约日 | 用第 3 步的结果：阶段还在发现问题、技术预研、方案论证，但预计签约日期在 60 天内 |

系统没有记录阶段变化的时间，所以「卡在某个阶段多久」**算不出来**。用上面几类信号代替，并在结论里说明判断依据。

用了预计签约日期、未梳理天数或金额排序时，插件会扫描最多 500 条。结果里 `localFilter.scanTruncated` 为 true 时，告诉用户只扫描了前 500 条，结论可能不全，建议按负责销售或阶段缩小范围。

### 5. 写结论和建议

按 `templates/analysis-report.md` 的结构写。要求：

- 开头一两句话给出总体判断，例如「本季度在跟商机 3200 万元，但 60% 停在方案论证之前，商务招标阶段只有 400 万元，按现在的节奏本季度能签的有限」。
- 每个判断都附上数字和出处。
- 建议落到具体项目和动作：哪个项目、谁负责、建议做什么（更新预计签约日期、补一次梳理、确认风险标记、推进到下一阶段等）。
- 金额单位万元。

## 常见问题

| 现象 | 处理 |
|---|---|
| 某个阶段汇总是 0 | 正常，写 0，不要省略这一行 |
| 问题项目太多 | 每类只列前 10 个，写明一共有多少个 |
| 用户问已签约或丢单的分析 | 查询加 `includeArchived=true`，或用 `projectStatus` 指定「项目签约」「项目丢单」，在结论里分开说 |
| 用户要看某个项目的详细进展 | 说明插件只能看列表字段；可以用「查数据」skill 查这个客户的日报，了解最近的跟进内容 |
