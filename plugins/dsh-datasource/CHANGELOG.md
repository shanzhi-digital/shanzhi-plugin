# 数据源插件更新记录

此插件独立于 DataHub 应用，仅涉及本仓插件及用户本机 DSH；不修改 DataHub 服务源码、业务数据库、受管提示词或部署。

## 0.9.0-local.13

- 修复关系 AI 将全源连线合并成一张大画布的问题，按有主表的业务组合批量保存多个独立草稿，整批校验和事务提交。
- 允许跨业务画布复用相同表及关联，按主表和完整关联集合去重，保留部分重叠的组合。
- 主表纳入画布语义、确认签名及全局成果指纹，历史无主表画布保持兼容；schema 保持 7。
- 共享服务升至 version 3，配套标注插件 0.1.0-local.11。

## 0.9.0-local.12

- 管理库升级至 schema 7，新增多表关系画布和每源唯一全局保存记录；提供 v6 → v7 保留原标注的手工迁移。
- 共享服务升至 version 2，提供画布草稿/确认/删除、第四步投影和全局保存；语义修改显式撤销全局认可，纯布局与同结构扫描保留。
- 关系依赖删除、停用和结构变化撤销人工确认且保留画布修复；恢复引用不自动确认。
- 新增同事务 readSavedResults 契约，未全局保存或认可失效返回 409，供后续建模使用；本轮不实现建模。
## 0.9.0-local.11

## 0.8.0-local.1（先前治理实现）

- 数据源详情以选表、选字段为主。只读扫描全部可访问表和字段，按需读取每表最多 10 行样例；目录刷新等待合并保存后直接返回。
- AI 辅助选表使用平级的「小智分析」「问题」页签，问题新增、查看、编辑、删除与泛化使用弹框；生成注释移到选表工具栏并确认当前勾选范围。
- 每次 AI 操作对应一个原生 DSH 会话，事件订阅 ready 后发送 prompt；分页读取后提交完整结果，事务保存成功才返回。不再使用持久任务队列、worker 或两秒状态轮询。
- 当前治理成果保存人工选择、审核、注释、字段示例和关联关系。取消、超时及重启后的旧会话拒绝访问和晚到提交；成功清理监听不取消正在返回的工具结果。
- MySQL 管理库使用 schema 3，共 6 张表，保存当前成果及最小会话访问范围，不保存任务详情。升级时手动执行一次独立重置 SQL，清除 10 张旧管理表，再由完整建表 SQL 初始化并重新配置业务连接；旧数据全清，不迁移、不导入旧 JSON，正常启动不清库。
