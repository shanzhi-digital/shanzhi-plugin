# 履约看板指标口径

`contract_dashboard` 返回的数据怎么理解。金额单位都是元。统计范围是你在履约系统里有权查看的合同；除合同数以外，已终止的合同都不计入。

## 节点的「应收（付）日期」

很多指标都按节点的应收日期算：有系统按触发规则算出的日期（`computedDate`）就用它，没有就用合同里写的固定日期（`plannedDate`）。两个都没有的节点（条件还没触发）不进逾期和月度统计。

## 汇总指标 `summary`（截至今天）

| 字段 | 含义 | 能不能直接引用 |
|---|---|---|
| `contractCount` | 合同总数 | 可以 |
| `activeCount`、`completedCount`、`draftCount` | 履约中、已完成、草稿状态的合同数 | 可以 |
| `totalAmount` | 合同总额，不含已终止的合同 | 可以 |
| `invoiceAmount` | 已关联到节点的发票金额合计 | 可以 |
| `receivedAmount` | 已关联到节点的收（付）款金额合计。没做三流核对、流水没关联到节点的，不算在里面 | 可以，但要说明口径 |
| `pendingInvoice` | 未开票金额：每份未终止合同的总额减去已开票，合计 | 可以 |
| `receivableAmount` | 应收日期已过、还没完成的节点金额合计（不扣已收） | 可以 |
| `overdueAmount` | 逾期金额：应收日期已过、节点未完成、没有停止检测的节点，节点金额减去已收后还剩的部分合计 | 可以 |
| `overdueCount` | 有逾期节点的合同数 | 可以 |
| `overdueRate` | 逾期金额 ÷ 合同总额 × 100，单位 % | 可以 |
| `revenue` | 销售合同：已收款 ÷ (1 + 平均税率) 估算的不含税收入；采购合同：已付款 | 销售合同的是估算，引用时写「按平均税率估算」 |
| `grossMargin` | 销售合同：按成本 = 收入 × 70% 估算，固定约等于 30%；采购合同：已付款 ÷ 合同总额 × 100 | **销售合同的不要引用**；采购合同的应称为「付款进度」，不是毛利 |

## 月度趋势 `rows`（1～12 月）

| 列 | 销售合同（`contractType=1`） | 采购合同（`contractType=2`） |
|---|---|---|
| 签约金额（元） | 签订日期在该月的合同总额 | 同左 |
| 收入金额（元） | 应收日期在该月的节点，已经收到的钱 | 应付日期在该月的节点，已经付出的钱（名字叫收入，实际是付款） |
| 支出金额（元） | 收入 × 70% 的估算值，**不要引用** | 应付日期在该月的节点，已经付出的钱（与「收入金额」相同） |
| 逾期应收应付（元） | 应收日期在该月、到今天仍未收齐的金额 | 应付日期在该月、到今天仍未付清的金额 |

要点：

- 月度回款是**按应收日期归月**的。比如 3 月到期、5 月才收到的钱，算在 3 月。写报告时说「应收日期在 X 月的节点已回款多少」，不要说「X 月到账多少」。
- 「逾期应收应付」是按今天回看的：越早的月份，越能反映长期拖欠。
- 不带 `contractType` 调用时，「收入金额」把销售回款和采购付款混在一起，「支出金额」全是 0，月报不要用这种数据。

## 异常判断（参考阈值，写报告时说明依据）

| 异常 | 判断方法 |
|---|---|
| 逾期偏高 | `overdueRate` 超过 5%；或报告月的「逾期应收应付」比上月增加 50% 以上 |
| 回款下滑 | 报告月「收入金额」比上月或前 3 个月平均值低 30% 以上 |
| 回款跟不上签约 | 年初至今「收入金额」合计不到「签约金额」合计的 30%，且已过半年 |
| 开票滞后 | `pendingInvoice` 超过 `totalAmount` 的 50% |
| 草稿积压 | `draftCount` 超过 5 份，或超过合同总数的 10% |

阈值只是提示，没有公司规定时说「按常见经验」，不要说成标准。
