# 合同风险排查

对一批履约中的合同做一次体检，产出一份按严重程度排好的风险清单。

## 什么时候用

- 用户想知道哪些合同有问题、要做合同体检或风险盘点。
- 不适用：只关心近期回款，用「回款节点跟进」skill（`contract-payment-followup`）；要分析某一份新合同的条款风险，用「导入并分析合同」skill（`contract-import-analyze`）。

## 开始前

- 需要已连接履约系统账户。任何工具返回 kind 为 `contract-sure-auth-required` 时：把 message 原样转告用户，停下等用户回复「继续」，不要重试或绕过。
- 弄清今天的日期，写进结果。
- 弄清范围：默认是全部履约中的合同。用户可以按合同类型、单位或负责人缩小范围。

## 查四类风险

| 风险 | 怎么查 | 需要的数据 |
|---|---|---|
| 缺合同原件 | 详情的 `documents` 里没有 `docType` 为 1（合同原件）的文件 | 合同详情 |
| 即将到期 | 合同 `endDate` 在今天起 60 天内，或已经过了 `endDate` 但合同还在履约中 | 合同详情 |
| 节点逾期 | 节点应收日期（`computedDate`，没有就 `plannedDate`）早于今天、`status` 不是 2（已完成）、`stopDetection` 不是 1、未收金额（`nodeAmount` − `receiptAmount`，空按 0）大于 0 | 合同详情 |
| 流水未匹配 | 未匹配流水的「合同编号」等于这份合同的编号，或「对方户名」和合同甲方、乙方一致 | 未匹配流水列表 |

严重程度怎么定，见 `references/severity-rules.md`。

## 步骤

### 1. 拉合同清单

调用 `contract_query`：`mode="list"`、`status=1`（履约中），按用户要求加 `contractType` 或 `keyword`，`pageSize=100`。`total` 大于已取条数时用 `pageNum` 翻页，最多取 500 条；超过就告诉用户只看了前 500 条，建议缩小范围。

### 2. 拉未匹配流水

调用 `contract_manage_flow`：`action="list_unmatched"`、`limit=200`。`hasMore` 为 true 时用 `offset` 等于 `nextOffset` 继续取，最多取 1000 条。把每条流水按「合同编号」和「对方户名」挂到第 1 步的合同上。挂不到任何合同的流水，单独统计条数和金额，放在结果最后。

### 3. 逐份查详情

对合同调用 `contract_query`：`mode="detail"`、`contractId`。

每查一份详情，回合末尾都会多一张「合同与票据原件」卡片，所以**一批最多查 20 份**。合同多于 20 份时，按这个顺序挑：

1. 列表里「逾期金额（元）」大于 0 的；
2. 第 2 步挂上了未匹配流水的；
3. 其余按「合同总额（元）」从大到小。

做完一批先交付结果，写清「共 N 份，已检查 M 份」，问用户要不要继续下一批。

### 4. 汇总成风险清单

同一份合同有多项风险时合成一行，严重程度取最高的那项。按严重程度、再按涉及金额从大到小排序。格式：

```
截至 YYYY-MM-DD，范围：履约中的销售和采购合同，共 N 份，本次检查 M 份。

### 概况
高风险 A 份、中风险 B 份、低风险 C 份；逾期未收合计 ¥X，未匹配流水 Y 条 ¥Z。

### 风险清单
| 严重程度 | 合同编号 | 合同名称 | 对方单位 | 风险项 | 关键数字 | 商务负责人 | 建议动作 |

### 未挂到合同的流水
共 K 条 ¥W，建议用「三流核对」skill 处理。

### 未检查的合同
还有 L 份没查详情（列表里没有逾期金额），需要的话我继续检查下一批。
```

「风险项」写短语，例如「终验款逾期 45 天，未收 52.00 万元」「缺合同原件」「12 月 31 日到期，尾款节点未完成」。「建议动作」要具体，见 `references/severity-rules.md` 里的建议写法。

## 需要用户确认的写入

排查本身只读。用户顺带要求处理时，下面这些会写入系统，**必须先把要写的内容列清楚、等用户明确确认后再执行**：

- 补传节点凭证：`contract_manage_flow`，`action="upload_node_evidence"`。
- 人工指定节点应收日期：`contract_manage_flow`，`action="set_node_manual_date"`。
- 把流水匹配到合同：交给「三流核对」skill（`contract-reconcile-flows`）的确认流程。

合同原件的补传目前没有对应工具：告诉用户到履约系统网页里上传，或者重新走「导入并分析合同」时带上原件（不要为了补原件重复创建合同）。

## 常见问题

| 现象 | 处理 |
|---|---|
| 合同详情没有 `endDate` | 「即将到期」这项记为「合同未填写结束日期」，严重程度按低处理 |
| 节点都没有应收日期（条件没触发） | 不算逾期；节点金额大、合同快到期时，提醒用户关注触发条件 |
| 一份合同风险项特别多 | 清单里写最重要的两三项，其余写「另有 N 项」，用户追问再展开 |
| 没有发现风险 | 直接说明检查了哪些合同、四类风险都没有发现，不要硬凑 |
