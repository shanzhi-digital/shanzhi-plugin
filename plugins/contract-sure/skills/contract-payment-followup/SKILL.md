# 回款节点跟进

把「哪些钱该收、哪些已经逾期、先催谁」理清楚，给出跟进清单和催款话术草稿。

## 什么时候用

- 用户关心近期该收或该付的款：本月、下月到期，或已经逾期。
- 默认看**销售合同的回款**（`contractType=1`）。用户说「付款」「要付给供应商的钱」时看**采购合同**（`contractType=2`），话术部分换成付款安排说明，不写催款。
- 不适用：只想看整体数字和趋势，用「履约月报」skill（`contract-performance-report`）；要全面排查合同风险，用「合同风险排查」skill（`contract-risk-review`）。

## 开始前

- 需要已连接履约系统账户。任何工具返回 kind 为 `contract-sure-auth-required` 时：把 message 原样转告用户，停下等用户回复「继续」，不要重试或绕过。
- 先弄清今天的日期（看对话上下文或系统时间），后面所有「本月」「逾期天数」都按今天算，并写进结果。

## 节点口径（判断到期和逾期全靠它）

合同详情里每个节点（`nodes` 里的一项）有这些字段：

| 字段 | 含义 |
|---|---|
| `nodeName`、`nodeAmount` | 节点名称、节点金额（元） |
| `computedDate` | 系统按触发规则算出的应收（付）日期 |
| `plannedDate` | 合同里写的固定日期 |
| `computedStatus` | 0 未计算、1 已计算、2 计算失败、3 条件还没满足 |
| `status` | 0 未开始、1 进行中、2 已完成 |
| `stopDetection` | 为 1 表示这个节点已停止检测，不算逾期 |
| `receiptAmount`、`invoiceAmount` | 已经分配到这个节点的收（付）款、开票金额；为空按 0 算 |
| `hasInvoice`、`hasAcceptance` | 是否已有发票、验收材料 |
| `conditionDesc` | 付款条件原文 |

- **应收日期** = `computedDate`，没有就用 `plannedDate`。两个都没有：条件还没触发，单独列为「待触发」，不算逾期。
- **未收金额** = `nodeAmount` − `receiptAmount`，小于等于 0 说明已收齐。
- **已逾期**：应收日期早于今天、`status` 不是 2、`stopDetection` 不是 1、未收金额大于 0。这和履约看板的逾期口径一致。
- **本月到期 / 下月到期**：应收日期落在本月（今天及以后）/ 下个自然月，且未收金额大于 0。

## 步骤

### 1. 拉合同清单

调用 `contract_query`：`mode="list"`、`status=1`（履约中）、`contractType` 按上面的选择、`pageSize=100`。`total` 大于本页条数时用 `pageNum` 翻页，直到取完或取满 500 条（超过就告诉用户只看了前 500 条，建议按负责人或单位缩小范围）。

用户指定了单位、负责人或合同时，把名称填进 `keyword`（它同时匹配合同号、名称、甲乙方、商务和交付负责人）。

### 2. 选出要看节点的合同

列表里没有节点明细，要逐份查详情。先挑：

1. 列表里「逾期金额（元）」大于 0 的合同，全部要看。
2. 其余按「合同总额 − 已收付金额」从大到小排，补足到 **20 份**。

合同总数不超过 20 份就全看。每查一份详情，回合末尾都会多一张「合同与票据原件」卡片，所以一批最多 20 份；还有没看的，在结果里说明「还有 N 份未检查」，问用户要不要继续下一批。

### 3. 查详情，按口径分类

对每份合同调用 `contract_query`：`mode="detail"`、`contractId` 填合同 ID。按上面的口径把节点分成：已逾期、本月到期、下月到期、待触发（只列金额较大的几个）。顺手记下：合同编号、名称、对方单位（销售合同一般是甲方，以合同为准）、商务负责人、节点是否已开票、是否已验收。

### 4. 排优先级

| 优先级 | 条件 |
|---|---|
| 高 | 逾期超过 30 天；或逾期且未收金额在本次结果里排前 20% |
| 中 | 其他逾期节点；本月到期但还没开票或还没验收（前置条件不满足，到期也收不到） |
| 低 | 本月到期且前置条件已满足；下月到期 |

同一档里按未收金额从大到小排。待触发的节点不排优先级，单独列一小节提醒「条件满足后才会产生应收日期」。

### 5. 写跟进清单和话术

按下面的格式回复。话术用 `templates/collection-messages.md` 里的模板，按「到期前提醒 / 刚逾期 / 逾期较久」挑一种，填好合同和节点信息，**只给高、中优先级的节点写**，每条不超过 150 字。

```
截至 YYYY-MM-DD，共检查 N 份履约中的销售合同（另有 M 份未检查）。

### 概况
已逾期 X 个节点，未收 ¥A；本月到期 Y 个，¥B；下月到期 Z 个，¥C。

### 跟进清单
| 优先级 | 合同编号 | 合同名称 | 对方单位 | 节点 | 应收日期 | 逾期天数 | 未收金额（元） | 发票/验收 | 商务负责人 | 建议动作 |

### 待触发节点（金额较大的）
……

### 催款话术草稿
1. 【合同编号 · 节点】……
```

金额超过 1 万时可以同时写成「万元」方便阅读，但表格里保留元。话术只是草稿：插件不会发消息，也不要替用户发。

## 需要用户确认的写入

跟进过程中用户可能顺带要求改系统里的数据，这两类是写入，**必须先把要写的内容列给用户、等用户明确确认后再调用**：

- 改节点应收日期：`contract_manage_flow`，`action="set_node_manual_date"`，要 `contractId`、`nodeId`、`date`，可选 `remark`。确认时列出：合同、节点、原日期、新日期、备注。
- 上传节点凭证（发票、收款凭证、验收材料）：`contract_manage_flow`，`action="upload_node_evidence"`，要 `contractId`、`nodeId`、`filePath`、`docType`（2 发票、3 收付款凭证、4 验收材料），可选 `amount`、`eventDate`。确认时列出：合同、节点、文件名、凭证类型、金额、日期。

用户只说「帮我处理一下」不算确认，要列清楚再问。一次确认只执行确认过的那几条。

## 常见问题

| 现象 | 处理 |
|---|---|
| 节点的 `computedStatus` 是 2（计算失败） | 应收日期算不出来，列进「待触发」，并提示用户检查触发规则，必要时人工指定日期（写入，要先确认） |
| 列表里逾期金额大于 0，详情里却找不到逾期节点 | 如实说明两边口径可能不同，以节点明细为准，并把这份合同列出来请用户核对 |
| 没有任何逾期和到期节点 | 直接说「本月、下月没有到期节点，也没有逾期」，并说明检查了多少份合同 |
| 合同太多，20 份看不完 | 先交付这一批的结果，再问用户是否继续，或者按负责人、单位缩小范围 |
